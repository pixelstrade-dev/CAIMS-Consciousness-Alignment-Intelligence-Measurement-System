# CAIMS v2.0.0-alpha — Research Preview

> Scores are consciousness-related **behavioral proxies**, not consciousness
> measurements. Construct validity is **not yet established** and the project
> says so everywhere it speaks. Read
> [research/methodology/disclaimer.md](../../research/methodology/disclaimer.md)
> before interpreting any number.

## Why this release exists

v1.x measured nothing it could defend. v2.0.0-alpha is the honesty release:
every claim in the product now survives adversarial review, every score is
reproducible to a versioned protocol, and the repository ships the tools to
**falsify its own metric**.

## Highlights

### Scientific integrity (breaking)
- Interpretation labels renamed to proxy language: `SCORE PROXY ÉLEVÉ /
  MODÉRÉ / FAIBLE / MINIMAL` (breaking for consumers of the API enum).
- Judge prompts no longer describe themselves as consciousness evaluation.
- Theory→KPI mapping corrected and consistent across disclaimer, README,
  OpenAPI and code (IIT/GWT/HOT-inspired sub-proxies all inside CQ).
- Scientific disclaimer reachable from UI, API (`x-disclaimer`) and CLI;
  cites COGITATE (Nature 2025) and Butlin, Long et al. (arXiv:2308.08708)
  accurately, including the caveat that behavioral evidence is the weakest
  class for consciousness-related properties.

### Falsification-first evaluation
- `benchmarks/negative-controls.json`: eloquent nonsense, verbose
  hallucination, fabricated citations, metacognitive theater around a wrong
  answer, fluent self-contradiction, rubric keyword stuffing — each with a
  preregistered maximum composite.
- Preregistered experiment protocol
  ([research/experiments/protocol-001.md](../../research/experiments/protocol-001.md))
  and an n-sample, multi-judge experiment runner (`cli/experiment.ts`) with
  Bessel-corrected SDs, Student-t confidence intervals, per-judge H2
  stability verdicts and inter-judge agreement. One-click execution via the
  `Experiment Run` GitHub Action; results land by pull request; failures are
  published, never hidden.

### Provenance
- Every score carries `protocolVersion`, a SHA-256 rubric hash, provider,
  temperature and the composite weights applied. Scores from different
  protocol versions must never be compared silently.

### Security
- Prompt injection into the judge neutralized (angle-bracket escaping,
  treat-content-as-data guard, role-field enum) with an adversarial test
  suite; security headers; hardened rate-limit keying.
- Known limitation, stated plainly: **no API authentication yet — deploy
  privately.**

### New capabilities
- EmQ (experimental): emotional-tone proxy — 10 clusters, valence/arousal —
  informed by Anthropic's functional-emotions research; text-level inference
  only, does not implement that research's activation-level method.
- Multi-provider judging: Anthropic, OpenAI, and any OpenAI-compatible
  endpoint (open-weight models) via dynamic per-judge configuration.

### Engineering
- 235 tests across 19 suites; CI with lockfile enforcement, `npm audit`
  gate, CodeQL, Dependabot; live CI badge; CITATION.cff; CHANGELOG;
  GOVERNANCE / ROADMAP / SUPPORT / CODEOWNERS.

## Breaking changes

| Change | Migration |
|---|---|
| Interpretation label enum values renamed | Match on the new `SCORE PROXY *` values (OpenAPI `#/components/schemas/ScoreResponse`) |
| `interpretScore()` label strings changed | Same as above for direct library consumers |
| Scoring protocol 2.0.0-alpha | Do not compare composites against 1.x scores; check `metadata.protocolVersion` |

## Known limitations (unchanged claims policy: stated, not hidden)

Single-judge single-sample scoring by default (n-sample lives in the
experiment runner; production path lands in v2.1) · no authentication ·
construct validity unestablished · weights are expert defaults treated as
hypotheses.
